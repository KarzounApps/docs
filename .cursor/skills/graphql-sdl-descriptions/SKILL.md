# GraphQL SDL descriptions

Strategy for public API reference docs generated by Mintlify from the filtered SDL (`GET /public-api.graphql` → `docs.json` → `/api-reference`).

Pilot (done): **Apps** — `apps`, `appsAdd`, supporting types/args. Apply the same pattern domain-by-domain.

## Goals

1. Integrators get actionable reference pages (auth, args, returns, errors) without leaving `/api-reference`.
2. Authors keep schema files thin; long copy lives in description modules.
3. Less repetition — explain once on the type; operations **link** instead of re-explaining.
4. Consistent voice — product language, fixed section order, shared link helpers.

## Two layers (do not mix)

| Layer | Owns | Examples |
| --- | --- | --- |
| **SDL descriptions** | Contract: what / args / returns / caveats / errors | `packages/core/.../descriptions/apps.ts` |
| **MDX guides** | Story: first call, rotate tokens, webhooks walkthrough | `docs/developers/getting-started/authentication.mdx` |

SDL must not paste full curl tutorials. Guides must not invent fields — they deep-link to the reference.

## File pattern

```
packages/<pkg>/src/.../schema/
  descriptions/
    _utils.ts              # d(), desc(), ref.* link helpers
    <domain>.ts            # long-form copy only
  <domain>.ts              # thin SDL structure; import * as D + desc()
```

Rules:

- Never put `"""` inside a description string.
- No resolver/helper names (`paginateQuery`, etc.).
- Prefer workspace / app token / `x-app-token` terminology (see `docs/AGENTS.md`).

## Operation description card

Use this order on every public query/mutation (omit empty sections):

```text
{One–two sentences: what it does}

{When to use / sibling relationship — prefer links}

{Warning / Danger / Info / Note callouts as needed}

${metaFooter(permission, relatedMarkdown)}
```

`metaFooter` is plain small text — no callouts/boxes (those already appear for Warnings/Notes and would overwhelm every page). Do **not** add Returns — Mintlify already shows the return type.

```html
<small>

*Auth* · `x-app-token` · required permission `{permission}`
<!-- or, when only requireLogin / moduleRequireLogin: -->
*Auth* · `x-app-token` · authenticated

*Related:* {deep links}

</small>
```

Pass `null` as the first `metaFooter` argument when there is no named permission action (login-only).

Side effects and errors belong in `<Note>` (or Warning) above the footer, not inside `metaFooter`.

Args and type fields each get a **one-liner** (defaults, soft-required rules, XOR constraints). Soft GraphQL-optional / runtime-required rules belong on the **argument**, not only in the op blurb.

## Link strategy (Mintlify `/api-reference`)

Mintlify generates one page per query, mutation, and named type. Slugs are **exact GraphQL names** (camelCase / PascalCase):

| Kind | URL |
| --- | --- |
| Hub | `/api-reference` |
| Query | `/api-reference/queries/{name}` e.g. `/api-reference/queries/apps` |
| Mutation | `/api-reference/mutations/{name}` e.g. `/api-reference/mutations/appsAdd` |
| Type | `/api-reference/types/{Name}` e.g. `/api-reference/types/App` |
| Playground | `/api-reference/playground` |
| MDX guide | `/developers/...` e.g. `/developers/getting-started/authentication` |

Use markdown links in SDL descriptions (Mintlify renders description markdown):

```md
Create credentials with [`appsAdd`](/api-reference/mutations/appsAdd).
Returns [`AppTokenResult`](/api-reference/types/AppTokenResult).
See [Authentication](/developers/getting-started/authentication).
```

### DRY rules with links

| Put the detail on… | Link from… |
| --- | --- |
| Type `App` (token hint `****last4`, locked permissions) | `apps`, `appDetail`, `appsEdit` |
| Type `AppTokenResult` (full JWT once) | `appsAdd` only |
| Arg `userGroupId` XOR `allowAllPermission` | `appsAdd` args — not copied into every Related blurb |
| Pagination defaults | Shared wording or link [Pagination](/developers/guides/pagination) |

**Do not** restate full type field docs inside every operation. One sentence + link is enough.

### Helpers

Use `ref` from `packages/core/src/data/schema/descriptions/_utils.ts`:

```ts
import { d, ref, metaFooter } from './_utils';

export const apps = d(`
List app credentials…

${metaFooter(
  'showDeveloper',
  `${ref.query('appDetail')}, ${ref.mutation('appsAdd')}, ${ref.auth()}`
)}
`);
```

## Behavior notes that belong in docs (when true)

- Masked secrets on list/detail (`****` + last 4) vs full secret only on create result types.
- Permissions locked after create → “mint new + remove old”.
- Soft-required args that GraphQL cannot express with `!`.
- `@deprecated` when a field exists for shape compatibility but must not be used as documented historically.

## Rollout

1. **Done — Apps** (`descriptions/apps.ts`) — gold pilot.
2. **Done — all other `packages/core` public domains** (descriptions modules + thin schemas):
   Tags, Customers, Companies, Fields, Products, Forms, Conformity, Contacts,
   Segments v2, Email templates, Users (RO), Structure (depts/branches RO),
   Activity events, Customer analytics.
3. **Out of scope here:** plugin subgraphs (inbox, tasks, webhooks, WhatsApp, automations, …).
4. **Blocked:** Brands mutations are in the public manifest but `brand.ts` is missing from core — restore schema or drop from manifest before documenting.
5. For each new domain later:
   - Add `descriptions/<domain>.ts`
   - Thin the schema file
   - Document types first, then ops that link to them
   - Export / sync `public-api.graphql` for local Mintlify (`gateway` `yarn export-public-schema --supergraph …`); deploy/restart core for live SDL
6. **Optional later:** CI lint that every `public-api-manifest.yaml` operation has a non-empty description and that `Related` lines use `/api-reference/` links where applicable.

## Definition of done (per domain)

- [ ] Op pages readable without leaving reference (auth + returns + caveats)
- [ ] Every arg documented
- [ ] Types carry field semantics; ops deep-link to types/siblings
- [ ] No internal implementation jargon
- [ ] MDX guides link to `/api-reference/…` instead of duplicating field tables
- [ ] `mint validate` / spot-check generated pages for the pilot ops

## Out of scope

- Arabic translations of generated English SDL text (shared `api-reference/`)
- Hand-written MDX pages that replace Mintlify GraphQL generation
- Documenting non-manifest (internal) operations
