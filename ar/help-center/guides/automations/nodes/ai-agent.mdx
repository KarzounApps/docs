## بطاقة سريعة

| | |
| --- | --- |
| **الفئة** | الذكاء الاصطناعي |
| **المدخل** | واحد |
| **المخارج** | **مكتمل** (انتهاء الجلسة) · **فشل** · مخرج مستقل لكل أداة/نية تُفعَّل |
| **الحقل الإلزامي** | ملف تعريف المساعد |

هذه العقدة تسلّم المحادثة **بالكامل** لمساعد ذكي محادثي — لا رسالة واحدة ثابتة، بل جلسة كاملة يتفاعل فيها المساعد مع العميل بحرية ضمن الحدود التي تضبطها.

## الحقول

| الحقل | ماذا يعني | الافتراضي |
| --- | --- | --- |
| **المساعد (ملف التعريف)** | أي ملف مساعد **مخصَّص** أنشأته في استوديو الوكلاء | — (إلزامي) |
| **توجيه احتياطي** | رسالة تُستخدم إن تعذّر تشغيل المساعد (وضع مستقل) | فارغ |
| **الأدوات واكتشاف النوايا** | نوايا محددة يستطيع المساعد اكتشافها وتوجيه المسار عند حدوثها | بلا |
| **تأخير تجميع الرسائل** | ثوانٍ ينتظرها المساعد ليجمع عدة رسائل متتالية من العميل قبل الرد عليها كوحدة واحدة | ٦٠ ثانية |
| **مهلة خمول الجلسة** | دقائق الصمت التي تُنهي الجلسة وتُقدِّم المسار للخطوة التالية | ٥ دقائق |
| **استخدم الملاحظات الداخلية** | يسمح للمساعد بقراءة ملاحظات الفريق الداخلية كسياق إضافي | معطّل |
| **تعليمات إضافية** | نص يُضاف لتوجيهات ملف التعريف، خاص بهذه العقدة فقط | فارغ |
| **احفظ الرد في حقل** | يحفظ آخر رد من المساعد في حقل على العميل | فارغ |
| **مستوى التفكير** | شدة "تفكير" النموذج قبل الرد (منخفض/متوازن/مرتفع/أقصى) — اتركه فارغاً لاستخدام إعداد ملف التعريف | إعداد الملف |
| **حجم السياق** | عدد الرسائل السابقة التي يراها المساعد من المحادثة (١ إلى ٥٠) | ٢٠ |

## ما هو "ملف تعريف المساعد"؟

يُنشأ ويُضبط في **استوديو الوكلاء** — مساحة مستقلة تحدد شخصية المساعد وقدراته بشكل شامل قبل أن تختاره في أي أتمتة:

| ما يحدده ملف التعريف | مثال |
| --- | --- |
| **الهوية** | الاسم، الوصف، الأيقونة |
| **الشخصية** | نغمة الحديث، أسلوب الرد، الجنس اللغوي، الصوت (إن استُخدم صوتاً) |
| **المعرفة** | مواضيع قاعدة المعرفة المرتبطة بالمساعد |
| **القدرات (Capabilities)** | الأدوات الحقيقية التي يستطيع المساعد استدعاءها بنفسه أثناء الحوار — بحث الإنترنت، قراءة صفحة، قاعدة المعرفة، تصفح كتالوج المنتجات، إدارة السلة، الاستعلام عن الطلبات، بدء الدفع، وغيرها. راجع [قدرات الوكيل الحقيقية](#قدرات-الوكيل-الحقيقية-الأدوات) أدناه |
| **التوجيهات** | تعليمات سلوكه العامة، وتعليمات تشكيل ردوده |
| **إعدادات النموذج** | درجة الحرارة (Temperature)، الحد الأقصى للرموز، مستوى التفكير الافتراضي |

عند اختيار الملف في هذه العقدة، تُدمَج تعليماته مع أي تعليمات إضافية تكتبها هنا خصيصاً لهذا المسار — فالملف عام قابل لإعادة الاستخدام في عدة أتمتات، وحقل "تعليمات إضافية" هو تخصيص محلي لهذه العقدة فقط.

<Warning>
منتقي الملفات في هذه العقدة يعرض **الملفات المخصَّصة فقط**، لا ملفات النظام الجاهزة. أنشئ ملفك في استوديو الوكلاء أولاً إن لم يظهر أي ملف مناسب.
</Warning>

## الأدوات واكتشاف النوايا: كيف تعمل فعلياً؟

هذا الحقل **ليس** صلاحية حرة للمساعد لاستدعاء أي إجراء في النظام. هو آلية **نوايا مسمّاة** تخبر المساعد: "إن اكتشفت في حديث العميل أن هذه النية حدثت، تصرّف بهذه الخطوات".

لكل أداة/نية تضيفها:

| الحقل | ماذا يعني |
| --- | --- |
| **الاسم** | اسم مختصر للنية (مثال: `تحويل_لموظف`) |
| **الوصف** | شرح للمساعد متى يعتبر هذه النية قد حدثت |
| **المعاملات** | معلومات يجمعها المساعد من المحادثة قبل تفعيل النية (اسم، وصف، إلزامية، حقل حفظ، نوع) |
| **المخرج التالي** | العقدة التي يتوجّه إليها المسار عند تفعيل هذه النية |

النظام يوفّر **نوايا جاهزة** كنقطة انطلاق يمكنك تعديلها:

| النية الجاهزة | الاستخدام |
| --- | --- |
| **تصعيد عميل غاضب** | يكتشف الغضب ويحوّل لموظف بشري |
| **حجز موعد** | يجمع تفاصيل الموعد المطلوب |
| **طلب توظيف** | يجمع معلومات المتقدم للوظيفة |
| **تحويل لموظف بشري** | طلب مباشر من العميل بالتحدث مع إنسان |
| **جمع معلومات العميل** | يجمع بيانات تعريفية أساسية |

كل نية مفعَّلة تصبح **مخرجاً مستقلاً على اللوحة** — تربطه بالعقدة المناسبة لما بعد اكتشاف تلك النية.

## قدرات الوكيل الحقيقية: الأدوات

لا تخلط بين "الأدوات واكتشاف النوايا" أعلاه، وبين **القدرات (Capabilities)** التي تفعّلها في **ملف تعريف المساعد** بالاستوديو. الفرق جوهري:

| | الأدوات واكتشاف النوايا (في هذه العقدة) | القدرات (في ملف التعريف) |
| --- | --- | --- |
| **ماذا تفعل** | تخبر المساعد "إن حدثت هذه النية، توجّه لهذا المخرج" | تمنح المساعد **استدعاء أدوات برمجية حقيقية** بنفسه أثناء الحوار |
| **الأثر على المسار** | تنشئ مخرجاً جديداً تربطه يدوياً بعقدة تالية | لا تُنشئ مخرجاً — تبقى المحادثة داخل هذه العقدة، والمساعد يستخدم الأداة ويكمل الرد |
| **مثال** | نية «تحويل لموظف بشري» ← تخرج من العقدة لعقدة تسليم | قدرة «تصفح كتالوج المنتجات» ← المساعد يبحث ويعرض نتائج فعلية دون مغادرة الجلسة |

بعبارة أخرى: **النوايا تُخرجك من هذه العقدة**، و**القدرات تجعل الحوار داخل هذه العقدة أذكى وأكثر فائدة**. مساعد بلا أي قدرة مفعّلة يستطيع فقط المحادثة النصية بمعرفته العامة والتوجيهات المكتوبة له — تفعيل القدرات هو ما يحوّله لوكيل قادر على تنفيذ عمل حقيقي.

راجع [أدوات الوكيل الذكي](/ar/help-center/guides/automations/ai-tools-actions) للمرجع الكامل لكل قدرة متاحة (بحث الإنترنت، قراءة صفحة، قاعدة المعرفة، البحث الدلالي والبصري في المنتجات، التوصيات الذكية)، و[العمليات والتجارة الإلكترونية](/ar/help-center/guides/automations/operations-actions) لقدرات السلة والطلبات والدفع عبر واتساب.

<Tip>
فعّل فقط القدرات التي يحتاجها استخدامك الفعلي. مساعد يحمل كل القدرات المتاحة ليس بالضرورة أفضل — كل قدرة إضافية تزيد فرصة أن يختار المساعد أداة غير مناسبة للسياق.
</Tip>

## المخارج الثلاثة (وأكثر)

| المخرج | متى يُسلك |
| --- | --- |
| **مكتمل** | انتهت الجلسة بصمت العميل بعد آخر رد (انقضاء مهلة خمول الجلسة) — المسار الطبيعي لإنهاء الحوار |
| **فشل** | تعذّر تشغيل المساعد (خطأ تقني أو استجابة غير صالحة) |
| **[اسم كل نية]** | العميل حقّق نية محددة، فيتوجّه المسار فوراً لمخرجها الخاص |

<Warning>
لا تربط "احتياج تحويل لموظف بشري" بمهلة الخمول فقط — استخدم **نية مخصصة** لذلك. مهلة الخمول تنتهي فقط عند **صمت العميل**، وليس عند طلبه المباشر للتحدث مع إنسان أثناء استمرار حديثه.
</Warning>

## تأخير تجميع الرسائل: لماذا يهم؟

عندما يكتب العميل عدة رسائل متتالية سريعة (مثال: "أريد استرجاع..." ثم "...الطلب رقم ١٢٣٤" في رسالة منفصلة)، تأخير التجميع يجعل المساعد **ينتظر** الثواني المحددة ليجمعها كسياق واحد قبل الرد — فلا يرد على الرسالة الأولى منفردة وكأنها طلب غير مكتمل.

القيمة الافتراضية **٦٠ ثانية** مناسبة لمعظم الحالات. قلّلها إن كانت طبيعة تواصل عملائك رسائل مكتملة ومنفردة، وزدها إن اعتاد عملاؤك تجزيء أفكارهم على رسائل متعددة.

## مهلة خمول الجلسة

الفرق الجوهري بينها وبين تأخير التجميع: هذه المهلة تحسب **صمت العميل الكامل بعد رد المساعد**، لا الفجوة بين رسائل متتالية منه. عند انقضائها بلا رد جديد من العميل، تُعتبر الجلسة منتهية ويتحرك المسار من مخرج **مكتمل**.

اضبطها حسب طبيعة المحادثة: جلسة استفسار سريع لا تحتاج أكثر من دقائق قليلة، بينما جلسة تتضمن انتظار العميل لإرفاق مستند أو التفكير في قرار تستحق مهلة أطول.

## حجم السياق والملاحظات الداخلية

- **حجم السياق** يحدد عدد الرسائل السابقة التي "يتذكرها" المساعد من نفس المحادثة (١ إلى ٥٠، الافتراضي ٢٠) — كافٍ لمعظم المحادثات، ويُنصح بزيادته فقط لمحادثات طويلة ومعقدة تحتاج تتبع سياق أبعد.
- **استخدم الملاحظات الداخلية** يمنح المساعد رؤية على ملاحظات فريقك الداخلية على نفس المحادثة كسياق إضافي — فعّله فقط إن كانت ملاحظات فريقك تحمل معلومات يفيد المساعد معرفتها، وتذكّر أن هذه الملاحظات قد تحتوي تعليقات داخلية لم تُكتب بنية أن يقرأها الذكاء الاصطناعي.

## أخطاء شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| ترك مخرج «فشل» بلا وجهة | خطأ تقني يوقف المسار صمتاً | وجّهه لتحويل بشري أو رسالة بديلة |
| توقع أن «مكتمل» يعني نية محققة | فهم خاطئ للمخرج | «مكتمل» = انتهاء الجلسة بصمت فقط، لا نجاح مهمة |
| نسيان ربط نية «تحويل لموظف» بمخرجها | العميل يطلب إنساناً والمساعد يستمر وحده | اربط كل نية بمخرج فعلي فوراً |
| اختيار ملف تعريف نظام جاهز | لا يظهر في المنتقي | أنشئ ملفاً مخصصاً في استوديو الوكلاء أولاً |
| تعليمات إضافية متعارضة مع توجيهات ملف التعريف | سلوك غير متوقع من المساعد | راجع توجيهات الملف قبل إضافة تعليمات محلية متضاربة |
| مهلة خمول قصيرة جداً لمحادثة تحتاج تفكيراً | إنهاء الجلسة قبل أن يقرر العميل | اضبط مهلة أطول لمحادثات تتطلب وقتاً |
