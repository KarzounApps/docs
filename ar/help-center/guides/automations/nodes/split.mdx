عندما تريد تجربة نسختين من رسالة أو مسار دون شروط بيانات، تحتاج توزيعاً بنسبة لا بقواعد.

عقدة **تقسيم A/B** توزّع العملاء على متغيّرات بنِسَب تضبطها، لكل متغيّر مخرج مستقل.

يشرح هذا الدليل إعداد المتغيّرات والنسب، وما يجب مراقبته بعد النشر.

## بطاقة سريعة

| | |
| --- | --- |
| **الفئة** | المنطق |
| **المدخل** | واحد |
| **المخارج** | مخرج واحد لكل متغيّر (٢ كحد أدنى، بلا سقف أعلى) |
| **أنواع التقسيم** | **نسبة (Percentage)** · **عشوائي (Random)** · **حقل (Field)** |
| **الافتراضي** | نسبة · متغيّران ٥٠٪ / ٥٠٪ |

هذه العقدة تفرّع المسار إلى عدة متغيّرات. النوع يحدد **كيف** يُختار المتغيّر — ليس دائماً توزيعاً بنسبة مئوية.

## أنواع التقسيم الثلاثة

| النوع في النموذج | ماذا يفعل | متى تستخدمه |
| --- | --- | --- |
| **Percentage Split** | اختيار موزون بالنسب التي تضبطها لكل متغيّر | اختبار A/B برسائل مختلفة بنسب ثابتة |
| **Random Split** | توزيع عشوائي عبر المتغيّرات (بدون الاعتماد على نسبك كوزن رئيسي كما في النسبة) | تقسيم حمل عشوائي بسيط |
| **Field Split** | توجيه حسب **قيمة حقل** تحدده — النسب تُصفَّر ولا تُستخدم | مدينة، وسم، خاصية عميل… بدل عشوائية |

للتوجيه بمنطق شرطي معقّد (عدة شروط AND/OR) استخدم [عقدة الشرط](/ar/help-center/guides/automations/nodes/condition) لا التقسيم.

## الحقول

| الحقل | ماذا يعني |
| --- | --- |
| **نوع التقسيم** | نسبة / عشوائي / حقل — انظر الجدول أعلاه |
| **الحقل (Field)** | يظهر عند نوع **حقل** — مسار الحقل الذي تُقارن قيمته بالمتغيّرات |
| **المتغيّرات (Variants)** | كل متغيّر له اسم/تسمية؛ في نوع الحقل أضف **القيمة** المطابقة؛ في النسبة أضف **النسبة** |
| **النسبة لكل متغيّر** | لـ Percentage (وذات صلة بـ Random حسب الواجهة) — من ٠ إلى ١٠٠ |
| **إضافة متغيّر** | يضيف متغيّراً جديداً (C، D...) — بلا حد أقصى في النظام |

## كيف يعمل التوزيع فعلياً؟ (نوع النسبة)

عند **Percentage**: كل متغيّر له **نسبة**. عند دخول عميل يُختار متغيّر عشوائياً **موزوناً بهذه النسب** — احتمال يساوي نسبة كل متغيّر من الإجمالي، وليس توزيعاً حتمياً متساوياً على كل دفعة صغيرة.

<Tip>
لو ضبطت ٧٠٪ / ٣٠٪، فمن كل ١٠٠ عميل تقريباً ٧٠ و٣٠ على المدى الطويل — لا على كل عشرة عملاء بالضبط.
</Tip>

عند **Field**: يطابق النظام قيمة الحقل المختار مع قيمة المتغيّر ويوجّه لذلك المخرج — لا عشوائية.

## هل يجب أن تساوي النسب ١٠٠٪؟

الواجهة تعرض إجمالي النسب وتُبرزه لتنبيهك إن لم يكن ١٠٠٪، لكنها **لا تمنعك من الحفظ** حتى لو لم يكتمل الإجمالي. من الناحية العملية، اجعل الإجمالي دائماً ١٠٠٪ لتفادي نتائج غير متوقعة — نسب لا تصل لـ١٠٠٪ تعني ببساطة أن الوزن النسبي بين المتغيّرات المتاحة هو ما يُستخدم، وقد لا يطابق توقعك الحرفي للنسبة.

## كم متغيّراً يمكن إضافته؟

**لا حد أعلى صريح** — تستطيع تجاوز A/B لإضافة C وD وما بعدها لتوزيع أكثر من مسارين. الحد الأدنى **متغيّران**؛ لا يمكن حذف الأخير المتبقي.

## متى تستخدمها؟

| الحالة | مناسبة؟ |
| --- | --- |
| اختبار رسالتين بنسب ثابتة | نعم — نوع **Percentage** |
| توزيع عشوائي على عدة مسارات | نعم — نوع **Random** |
| توجيه حسب قيمة حقل واحدة (مدينة، رمز…) | نعم — نوع **Field** |
| منطق شرطي مركّب (عدة شروط) | لا — استخدم [عقدة الشرط](/ar/help-center/guides/automations/nodes/condition) |

## مثال عملي: اختبار عرضين على واتساب

1. **مشغّل** أو حملة بقناة الأتمتة تدخل عملاء العرض التجريبي.
2. **تقسيم A/B**: المتغيّر A بنسبة ٥٠٪ والمتغيّر B بنسبة ٥٠٪.
3. مخرج A ← رسالة بعرض خصم ١٠٪ ثم سؤال «هل تريد إتمام الطلب؟».
4. مخرج B ← رسالة بعرض شحن مجاني ثم نفس السؤال.
5. بعد أسبوع، قارن نسبة من أكمل الطلب من كل مخرج عبر [سجل التنفيذ](/ar/help-center/guides/automations/execution-history) وتقارير الحملات — لا تغيّر النسب أثناء الاختبار وإلا تفسد المقارنة.

## أخطاء شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| ترك نسبة متغيّر فارغة أو صفر عمداً بلا وعي | لن يدخل أي عميل هذا المتغيّر | تحقق من الإجمالي قبل النشر |
| توقع توزيع متساوٍ حتمي على كل عشرة عملاء | تفاوت طبيعي في عدد قليل من العملاء | التوزيع احتمالي، يستقر على المدى الطويل |
| استخدام **Percentage** بينما تريد مطابقة حقل | توزيع عشوائي بلا علاقة بالقيمة | اختر نوع **Field** أو عقدة الشرط |
| نسب لا تجمع ١٠٠٪ بدون قصد | نتيجة غير متوقعة | راجع الشعار/الإجمالي في الواجهة قبل النشر |
