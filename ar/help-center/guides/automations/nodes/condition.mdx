عندما يحتاج المسار فرعين مختلفين حسب بيانات العميل أو المحادثة، الرسالة الثابتة لا تكفي.

عقدة **شرط** تفحص القواعد في اللحظة وتتفرّع إلى مخرج **تطابق** أو **بدون تطابق** — دون انتظار رد من العميل.

يشرح هذا الدليل بنية المجموعات والقواعد، وكيف يفوز أول تطابق متسلسل، وعوامل المقارنة حسب نوع الحقل.

## بطاقة سريعة

| | |
| --- | --- |
| **الفئة** | المنطق |
| **المدخل** | واحد |
| **المخارج** | مخرج **تطابق** لكل مجموعة + مخرج واحد **بدون تطابق** |
| **الحد الأدنى** | مجموعة واحدة، بها قاعدة واحدة على الأقل |

هذه العقدة **لا تنتظر** — تفحص بيانات العميل والمحادثة **في اللحظة** وتوجّه المسار فوراً حسب أول مجموعة تتحقق.

## البنية: مجموعات، وكل مجموعة قواعد

العقدة تحتوي **مجموعات شرط** (Groups)، وكل مجموعة تحتوي **قواعد** (Rules):

```
مجموعة ١: [قاعدة أ] و/أو [قاعدة ب] و/أو [قاعدة ج]  →  مخرج تطابق ١
مجموعة ٢: [قاعدة د]                                →  مخرج تطابق ٢
...
بدون تطابق (إن لم تتحقق أي مجموعة)                  →  مخرج واحد مشترك
```

كل قاعدة: **حقل** (من بيانات العميل/المحادثة) + **عامل مقارنة** + **قيمة** (حسب العامل).

## الأهم: كيف تتحقق العلاقة بين المجموعات؟

هذه أدق نقطة في هذه العقدة، ويكثر الخلط فيها:

<Warning>
**العلاقة بين المجموعات المختلفة ليست «و» ولا «أو» عامة — بل فحص متسلسل بترتيب الظهور، وأول مجموعة تتحقق شروطها هي التي تفوز.** بمعنى: النظام يفحص المجموعة الأولى؛ إن تحققت، ينطلق من مخرجها **ويتوقف** عن فحص باقي المجموعات. إن لم تتحقق، يفحص المجموعة الثانية، وهكذا. فقط إن لم تتحقق **أي** مجموعة، يُسلك مخرج «بدون تطابق».
</Warning>

أما **عامل التطابق داخل المجموعة نفسها** (و/أو)، فهو ما يحدد العلاقة بين قواعد تلك المجموعة فقط:

| عامل المجموعة | يعني |
| --- | --- |
| **و (AND)** | يجب أن تتحقق **كل** القواعد داخل هذه المجموعة معاً |
| **أو (OR)** | يكفي أن تتحقق **قاعدة واحدة** من قواعد هذه المجموعة |

<Tip>
رتّب مجموعاتك من **الأكثر تحديداً إلى الأقل تحديداً**. إن وضعت مجموعة عامة جداً في الأول، ستفوز دائماً وتحجب المجموعات الأكثر دقة الموضوعة بعدها.
</Tip>

## عوامل المقارنة حسب نوع البيانات

يتغيّر عامل المقارنة المتاح تلقائياً حسب نوع الحقل الذي تختاره:

| نوع الحقل | العوامل المتاحة |
| --- | --- |
| **نص** | يساوي · لا يساوي · يحتوي · لا يحتوي · تم إسناده · لم يتم إسناده |
| **رقم** | يساوي · لا يساوي · أكبر من · أصغر من · تم إسناده · لم يتم إسناده |
| **صحيح/خطأ (Boolean)** | صحيح · خطأ · تم إسناده · لم يتم إسناده |
| **وقت** | يساوي · لا يساوي · بعد · قبل · تم إسناده · لم يتم إسناده |
| **تاريخ** | يساوي (تاريخ محدد) · لا يساوي · بعد · قبل · دقائق قبل/بعد · أيام قبل/بعد · الموعد خلال نطاق زمني · الموعد منتهٍ · تاريخ صالح · تاريخ غير صالح |

عوامل مثل **«تم إسناده»** و**«صحيح»** و**«تاريخ صالح»** لا تحتاج قيمة إضافية — تكفي وحدها كقاعدة.

## أمثلة عملية

| السيناريو | الإعداد |
| --- | --- |
| عميل VIP وطلبه أكبر من ٥٠٠ ريال | مجموعة واحدة، عامل «و»: `الوسم = VIP` و `قيمة_الطلب > 500` |
| عميل جديد أو عائد بعد ٣٠ يوماً | مجموعة واحدة، عامل «أو»: `تاريخ_أول_زيارة تم إسناده حديثاً` أو `آخر_زيارة قبل 30 يوماً` |
| توجيه حسب المدينة (ثلاث مدن مختلفة) | ثلاث مجموعات مستقلة، كل واحدة قاعدة واحدة: `المدينة = الرياض` / `= جدة` / `= الدمام`، وبدون تطابق لباقي المدن |

## متى تستخدم مجموعة واحدة، ومتى عدة مجموعات؟

| الحاجة | البنية الصحيحة |
| --- | --- |
| شرط واحد مركّب من عدة قواعد بعلاقة واحدة (كلها و، أو كلها أو) | **مجموعة واحدة** بعدة قواعد |
| عدة مسارات بديلة كل واحد بمنطقه المستقل (توجيه متعدد) | **عدة مجموعات**، كل واحدة قاعدتها/قواعدها الخاصة |

## أخطاء شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| افتراض أن كل المجموعات تُفحص وتجمع نتائجها | فهم خاطئ للمسار الناتج | تذكّر: أول مجموعة تتحقق تفوز وتوقف الفحص |
| مجموعة عامة موضوعة أولاً | تحجب مجموعات أدق موضوعة بعدها | رتّب من الأكثر تحديداً للأقل |
| ترك «بدون تطابق» بلا وجهة | العملاء غير المطابقين يتوقفون بصمت | وجّههم لمسار افتراضي أو تحويل بشري |
| استخدام «يحتوي» على حقل رقمي | لا يظهر كخيار | العوامل تُفلتَر تلقائياً حسب نوع الحقل |
| قاعدة على حقل لم يُملأ لأي عميل بعد | لا مجموعة تتحقق أبداً | تحقق أن الحقل يُعبَّأ فعلياً (من سؤال، تطبيق، أو استيراد) قبل الاعتماد عليه |
