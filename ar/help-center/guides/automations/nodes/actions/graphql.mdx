عندما تحتاج عملية من واجهة كرزون الداخلية لا يغطيها إجراء جاهز، لا تخرج إلى الإنترنت عبثاً.

إجراء **GraphQL الداخلي** يستدعي واجهة كرزون البرمجية من داخل المسار — بخلاف طلب HTTP للأنظمة الخارجية.

يشرح هذا الدليل الحقول والفرق عن HTTP.

## بطاقة سريعة

| | |
| --- | --- |
| **الاسم البرمجي** | `api` |
| **الفئة في المنتقي** | متقدّم |
| **أين يعيش** | إجراء واحد داخل [عقدة الإجراء](/ar/help-center/guides/automations/nodes/actions/overview) |
| **يستهدف** | واجهة كرزون البرمجية الداخلية (Internal GraphQL API) — لا أنظمة خارجية |

مختلف عن [طلب HTTP](/ar/help-center/guides/automations/nodes/actions/http-request): HTTP يخرج إلى الإنترنت، بينما **GraphQL الداخلي** يتحدث مع نفس واجهة كرزون التي تبني عليها المنصة.

## الحقول

| الحقل | ماذا يعني |
| --- | --- |
| **نوع العملية** | استعلام قراءة (**Query**) أو عملية تعديل (**Mutation**) |
| **اسم العملية** | الاسم الدقيق للعملية (Operation Name) |
| **المتغيرات** | قائمة مفتاح/قيمة، تدعم [متغيرات المسار](/ar/help-center/guides/automations/nodes/actions/overview#المتغيرات-الديناميكية) (`{{...}}`) |
| **حقول الاستجابة** *(اختياري)* | حقول محددة تريد استرجاعها بدل الاستجابة الكاملة |

## مثال استعلام واستجابة

الأسماء أدناه **توضيحية** — استبدلها بأسماء العمليات الحقيقية في حسابك / وثائق API.

**متغيرات العملية (مثال)**

```json
{
  "id": "{{customerId}}"
}
```

**شكل الاستعلام المفاهيمي**

```graphql
query customerDetail($id: String!) {
  customerDetail(_id: $id) {
    _id
    firstName
    primaryPhone
    state
  }
}
```

**استجابة ناجحة (مثال مبسّط)**

```json
{
  "data": {
    "customerDetail": {
      "_id": "64f0a1b2c3d4e5f678901234",
      "firstName": "سارة",
      "primaryPhone": "+9665xxxxxxx",
      "state": "customer"
    }
  }
}
```

اربط الحقول التي تحتاجها عبر **حقول الاستجابة** أو معالجة لاحقة بـ[عمليات JSON](/ar/help-center/guides/automations/nodes/actions/json-operations).

**خطأ تحقق (مثال)**

```json
{
  "errors": [
    {
      "message": "Variable \"$id\" of required type \"String!\" was not provided."
    }
  ]
}
```

## لماذا يوجد هذا الإجراء؟

بعض العمليات على بيانات كرزون أدق أو أخص من أن تغطيها إجراءات جاهزة عامة. الوصول المباشر لواجهة API الداخلية يغطي هذه الحالات دون انتظار ميزة جديدة في المنتقي.

## متى تستخدمه؟

| احتياجك | الأنسب |
| --- | --- |
| قراءة أو تعديل بيانات كرزون بدقة برمجية | GraphQL الداخلي |
| عملية شائعة (إسناد، وسم، خاصية) | إجراء جاهز |
| خدمة خارجية على الإنترنت | [طلب HTTP](/ar/help-center/guides/automations/nodes/actions/http-request) |

## أخطاء شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| اسم عملية غير دقيق | فشل صامت أو خطأ غامض | تأكد من الاسم مع فريقك التقني قبل النشر |
| استخدامه لعملية لها إجراء جاهز | تعقيد بلا فائدة | استخدم الإجراء الجاهز أولاً |
| متغيرات لا تطابق توقّع العملية | فشل التحقق | تحقق من نوع كل متغير |
| عدم تحديد حقول الاستجابة عند الحاجة لقيمة واحدة | استجابة ضخمة صعبة | حدد الحقول المطلوبة فقط |
