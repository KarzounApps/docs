## بطاقة سريعة

| | |
| --- | --- |
| **الاسم البرمجي** | `api` |
| **الفئة في المنتقي** | متقدّم |
| **أين يعيش** | إجراء واحد داخل [عقدة الإجراء](/ar/help-center/guides/automations/nodes/actions/overview) |
| **يستهدف** | واجهة كرزون البرمجية الداخلية نفسها (Internal GraphQL API) — لا أنظمة خارجية |

هذا الإجراء مختلف عن [طلب HTTP](/ar/help-center/guides/automations/nodes/actions/http-request): طلب HTTP يخرج إلى الإنترنت، بينما **GraphQL الداخلي** يتحدث مباشرة مع نفس الواجهة البرمجية التي تُبنى عليها منصة كرزون كاملة — أي عملية تقدر تنفّذها الواجهة الأمامية، يقدر هذا الإجراء تنفيذها من داخل مسار أتمتة.

## الحقول

| الحقل | ماذا يعني |
| --- | --- |
| **نوع العملية** | استعلام قراءة (**Query**) أو عملية تعديل (**Mutation**) |
| **اسم العملية** | الاسم الدقيق للعملية في واجهة كرزون البرمجية (Operation Name) |
| **المتغيرات** | قائمة مفتاح/قيمة تُمرَّر للعملية، تدعم [متغيرات المسار](/ar/help-center/guides/automations/nodes/actions/overview#المتغيرات-الديناميكية) (`{{...}}`) |
| **حقول الاستجابة** *(اختياري)* | حقول محددة تريد استرجاعها فقط من نتيجة العملية، بدل الاستجابة الكاملة |

<Info>
**وسائط مطلوبة:** محرر GraphQL الداخلي مفتوحاً بنوع Query واسم عملية ظاهر، مع صفّي متغيرات أحدهما يستخدم `{{...}}`، وقسم حقول الاستجابة مع حقلين محددين.
المسار المقترح: `/images/help/automations/action-graphql-form.webp`
</Info>

<Warning>
هذا الإجراء يتطلب معرفة دقيقة بأسماء العمليات (Operations) وبنيتها في واجهة كرزون البرمجية. استخدمه فقط إن كنت تعرف بالضبط العملية التي تريد استدعاءها، أو بمساعدة فريق تقني يملك هذه المعرفة.

لعمليات عامة وشائعة على بيانات العميل أو المحادثة — إسناد، وسم، تحديث خاصية، حل محادثة — توجد إجراءات جاهزة أبسط وأكثر أماناً لا تحتاج معرفة برمجية:

- [الإسناد والوسوم والملاحظات](/ar/help-center/guides/automations/assign-tag-note)
- [تحديث خاصية العميل](/ar/help-center/guides/automations/nodes/actions/set-property)
</Warning>

## لماذا يوجد هذا الإجراء أصلاً؟

بعض العمليات على بيانات كرزون الداخلية أدق أو أخص من أن تغطيها إجراءات جاهزة عامة — مثال: قراءة تفصيلية لسجل معين، أو تنفيذ عملية إدارية نادرة الاستخدام لا تستدعي بناء إجراء جاهز خاص بها. في هذه الحالات، الوصول المباشر لواجهة API الداخلية أسرع من انتظار ميزة جديدة.

## متى تستخدمه؟

| احتياجك | الأنسب |
| --- | --- |
| قراءة أو تعديل بيانات كرزون الداخلية بدقة برمجية | GraphQL الداخلي |
| عملية شائعة على العميل أو المحادثة (إسناد، وسم، خاصية) | إجراء جاهز — أبسط وأقل عرضة للخطأ |
| جلب أو إرسال بيانات لخدمة خارجية على الإنترنت | [طلب HTTP](/ar/help-center/guides/automations/nodes/actions/http-request) |

## أخطاء شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| اسم عملية غير دقيق | فشل صامت أو خطأ غامض عند التنفيذ | تأكد من الاسم مع فريقك التقني قبل النشر |
| استخدامه لعملية بسيطة لها إجراء جاهز | تعقيد بلا فائدة، وصعوبة صيانة لاحقاً | استخدم الإجراء الجاهز المتاح أولاً |
| متغيرات لا تطابق ما تتوقعه العملية | فشل التحقق (Validation) في واجهة API | تحقق من نوع كل متغير قبل الربط |
| عدم تحديد حقول الاستجابة عند الحاجة لقيمة واحدة فقط | استجابة ضخمة يصعب التعامل معها لاحقاً | حدد حقول الاستجابة المطلوبة فقط |
