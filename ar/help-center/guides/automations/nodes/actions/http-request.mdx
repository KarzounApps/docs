عندما لا يوجد تطبيق جاهز أو تحتاج طلباً مخصصاً لأي واجهة على الإنترنت، المسار يصبح عميل API.

إجراء **طلب HTTP** داخل عقدة الإجراء يضبط الطريقة والمصادقة والجسم والاستجابة — بأسلوب قريب من Postman.

يشرح هذا الدليل تبويبات المحرر ومخرج الفشل وكيفية الاختبار الفردي قبل الاعتماد عليه.

## بطاقة سريعة

| | |
| --- | --- |
| **الاسم البرمجي** | `externalApiRequest` |
| **الفئة في المنتقي** | متقدّم |
| **أين يعيش** | إجراء واحد داخل [عقدة الإجراء](/ar/help-center/guides/automations/nodes/actions/overview) |
| **المخرج** | رئيسي + مخرج فشل مستقل |

طلب HTTP يحوّل المسار إلى عميل API: أي نظام له واجهة برمجية على الإنترنت يصبح خطوة في الأتمتة. المحرر بأسلوب Postman بخمس تبويبات.

## الطريقة (Method)

`GET` · `POST` · `PUT` · `PATCH` · `DELETE` — تحدد نوع العملية على الرابط المستهدف.

## التبويبات الخمسة

### ١. المعاملات (Params)

معاملات الرابط (Query Parameters) على شكل صفوف مفتاح/قيمة. كل صف له **مفتاح تفعيل مستقل** — تستطيع تجهيز معامل ثم تعطيله مؤقتاً دون حذفه.

### ٢. الرؤوس (Headers)

رؤوس HTTP مخصصة بنفس أسلوب مفتاح/قيمة. استخدمها لـ `Content-Type`، رموز مصادقة إضافية، أو رؤوس يطلبها النظام الخارجي.

### ٣. المحتوى (Body)

| نوع المحتوى | متى تستخدمه |
| --- | --- |
| **بلا محتوى** | طلبات `GET`/`DELETE` التي لا تحتاج جسم طلب |
| **نص خام (Raw)** | JSON مكتوب يدوياً، أو نص عادي |
| **نموذج (Form)** | `application/x-www-form-urlencoded` |
| **GraphQL** | استعلام GraphQL خارجي + متغيراته كـJSON — لواجهات GraphQL **خارجية** (لواجهة كرزون الداخلية استخدم [GraphQL الداخلي](/ar/help-center/guides/automations/nodes/actions/graphql)) |

### ٤. المصادقة (Auth)

| النوع | الحقول |
| --- | --- |
| **بلا مصادقة** | — |
| **Basic** | اسم مستخدم + كلمة مرور |
| **Bearer** | رمز مصادقة واحد (Token) في رأس `Authorization` |

### ٥. الاستجابة (Response)

1. اضغط **إرسال** لتنفيذ الطلب بالقيم الحالية (أو قيم الاختبار).
2. تظهر الاستجابة كـJSON قابل للتصفح.
3. اختيارياً: **معالجة مسبقة بكود JavaScript** قبل الربط.
4. انقر أي قيمة لإضافتها كـ**ربط (Mapping)** إلى حقل عميل أو متغير مسار.

## المتغيرات الديناميكية وقيم الاختبار

كل حقل يقبل **متغيرات المسار** (`{{...}}`). لكل حقل أيضاً **قيمة اختبار** (شارة test) تُستخدم فقط عند الضغط على **إرسال** أثناء البناء — دون استبدال القيمة الحقيقية عند التشغيل الحي.

## مثال طلب واستجابة

نموذج شائع: جلب حالة شحنة برقم تتبع محفوظ في متغير مسار.

**طلب (مثال `GET`)**

```http
GET https://shipping.example.com/api/v1/track?number={{tracking_number}} HTTP/1.1
Authorization: Bearer {{shipping_token}}
Accept: application/json
```

**جسم طلب `POST` (مثال إنشاء تذكرة دعم خارجية)**

```json
{
  "customer_phone": "{{customer.primaryPhone}}",
  "subject": "متابعة طلب من واتساب",
  "body": "{{last_customer_message}}",
  "priority": "normal"
}
```

**استجابة ناجحة (مثال)**

```json
{
  "ok": true,
  "data": {
    "tracking_number": "SA123456789",
    "status": "out_for_delivery",
    "status_label_ar": "خارج للتسليم",
    "eta": "2026-08-18"
  }
}
```

اربط مثلاً `data.status` أو `data.status_label_ar` بمتغير مسار، ثم فرّع بـ[شرط](/ar/help-center/guides/automations/nodes/condition).

**استجابة فشل (مثال)**

```json
{
  "ok": false,
  "error": {
    "code": "NOT_FOUND",
    "message": "Tracking number not found"
  }
}
```

إن لم تكن الحالة `200` أو `201`، يُسلك **مخرج الفشل** إن كان موصولاً.

## عند الفشل

إن لم يرجع الطلب بحالة `200` أو `201`، يُسلك **مخرج الفشل** المخصص لهذا الإجراء إن كان موصولاً؛ وإلا يتوقف المسار بخطأ صامت.

<Warning>
دائماً وصّل مخرج الفشل بخطوة بديلة — رسالة للعميل، تنبيه لفريقك، أو تسليم لموظف. طلب HTTP بلا مخرج فشل موصول يعني أن أي انقطاع في الخدمة الخارجية يوقف المسار بصمت.
</Warning>

## متى تستخدمه؟

| احتياجك | الأنسب |
| --- | --- |
| جلب أو إرسال بيانات لأي خدمة خارجية | طلب HTTP |
| قراءة أو تعديل بيانات كرزون الداخلية | [GraphQL الداخلي](/ar/help-center/guides/automations/nodes/actions/graphql) |
| منطق حسابي أو تحويل قبل/بعد الطلب | [دالة JavaScript](/ar/help-center/guides/automations/nodes/actions/js-function) |
| تنظيف استجابة JSON معقدة | [عمليات JSON](/ar/help-center/guides/automations/nodes/actions/json-operations) |
| تطبيق مثبَّت له إجراء جاهز | [استخدام التطبيقات في الأتمتة](/ar/help-center/guides/automations/apps/use-in-automations) |

## مثال عملي: جلب حالة شحنة من نظام خارجي

1. العميل يرسل رقم التتبع ([سؤال](/ar/help-center/guides/automations/nodes/question) يحفظ الإجابة).
2. **طلب HTTP** — `GET` إلى واجهة شركة الشحن مع رقم التتبع ومصادقة Bearer إن لزم.
3. اختبر الطلب بقيمة اختبار في تبويب الاستجابة قبل النشر.
4. اربط حقل الحالة من الاستجابة بمتغير مسار.
5. [شرط](/ar/help-center/guides/automations/nodes/condition): إن «تم التسليم» أرسل شكر، وإلا أرسل الحالة + [متابعة](/ar/help-center/guides/automations/wait-and-follow-up).
6. وصّل **مخرج الفشل** برسالة ثم **تسليم إلى موظف بشري**.

## أخطاء شائعة

| الخطأ | النتيجة | الصواب |
| --- | --- | --- |
| بلا مخرج فشل موصول | انقطاع الخدمة يوقف المسار | وصّل مخرج الفشل لمسار بديل |
| بيانات حقيقية في حقول الاختبار | تسريب عند مشاركة الشاشة | قيم اختبار مصطنعة دائماً |
| نشر بلا اختبار بزر **إرسال** | خطأ يُكتشف من العميل | اختبر قبل النشر |
| نسيان `Content-Type` عند إرسال JSON | الخادم يرفض أو يفسّر خطأ | طابق الرأس مع نوع المحتوى |
| ترتيب إجراء يعتمد على نتيجة لاحقة | قيمة فارغة | رتّب الإجراءات حسب الاعتماد |
