---

Markdown لغة بسيطة تكتب بها مقالاتك في كرزون: يقرأها الإنسان بسهولة، ويعرضها الموقع بوضوح، ويفهمها المساعد عند الإجابة من قاعدة المعرفة. تعلّمها مرة، واستخدمها في كل مقالة.

## لماذا Markdown؟

النص العادي بلا هيكل يصعب قراءته على الموظف والعميل، ويصعب على المساعد استخراج الإجابة الصحيحة. Markdown يضيف عناوين، قوائم، وروابط **بدون** ترك المحرر إلى أدوات تنسيق معقّدة.

| لمن | ماذا يقدّم |
| --- | --- |
| **أنت والفريق** | كتابة سريعة في المحرر، معاينة فورية، نسخ بين المقالات بلا فقدان الشكل |
| **العميل** | صفحة مساعدة مقروءة: عناوين، خطوات، جداول |
| **المساعد والأتمتة** | هيكل واضح (عنوان → فقرة → قائمة) يسهّل استرجاع المعرفة المنشورة |

نعتبر Markdown **لغة مشتركة** بين الإنسان والذكاء: أنت تكتب المعنى والهيكل، والنظام يعرضه للزائر ويُفهرسه للمساعد. لذلك هي الطريقة الأنسب لمحتوى قاعدة المعرفة في كرزون — وليست «زخرفة اختيارية».

<Info>
**وسائط مطلوبة:** محرر Markdown بجانب معاينة لنفس المقالة.  
المسار المقترح: `/images/help/knowledge-base/markdown-editor-preview.webp`
</Info>

## لماذا تتعلّمه الآن؟

- محرر قاعدة المعرفة يعتمد **Markdown فقط** كمصدر للمحتوى — راجع [كتابة المقالة](/ar/help-center/guides/knowledge-base/write).
- مقالة منظّمة تُنشر أفضل للعميل وللمساعد من فقرة طويلة بلا عناوين — راجع [الاستخدام مع الذكاء](/ar/help-center/guides/knowledge-base/with-ai).
- نفس الرموز تعمل في كثير من أدوات الفريق والمساعدين؛ مهارة واحدة تخدم أكثر من شاشة.

لا تحتاج أن تصبح مطوّراً: بضعة رموز كافية لـ ٩٠٪ من مقالات الدعم والسياسات.

## قواعد سريعة قبل الأمثلة

1. اكتب في المحرر داخل مجلد فئة، ثم استخدم **معاينة** من لوحة الخصائص.
2. احفظ (**⌘S** / **Ctrl+S**) قبل الحكم على الشكل النهائي.
3. للعربية: اكتب العناوين والجمل بالعربية؛ الأسطر العربية تُحاذى لليمين في المحرر تلقائياً.
4. لا تلصق من Word/Docs بتنسيق مخفي — انسخ نصاً نظيفاً ثم أضف رموز Markdown بنفسك.

## العناوين

العناوين تقسم المقالة إلى أقسام يقفز إليها القارئ ويستدل بها المساعد.

```markdown
# عنوان رئيسي للمقالة (استخدمه نادراً إن كان عنوان الخصائص كافياً)

## قسم أساسي

### فرع داخل القسم
```

| استخدم | لا تستخدم |
| --- | --- |
| `##` و `###` لتقسيم سياسة أو دليل خطوات | عنواناً واحداً طويلاً بلا أقسام |
| عنواناً يطابق سؤال العميل («سياسة الاسترجاع») | عناوين غامضة («ملاحظات»، «عام») |

## التأكيد والتمييز

```markdown
هذا **مهم للعميل**.
هذا *تأكيد خفيف*.
هذا `رمز أو حقل في الواجهة` مثل زر **New article**.
```

في مقالات كرزون: ضع أسماء الأزرار والحقول بين `` ` `` أو بخط عريض حتى لا تختلط مع النص التشغيلي.

## القوائم والخطوات

للخطوات المتسلسلة استخدم قائمة مرقّمة؛ للخيارات أو الشروط قائمة نقطية.

```markdown
1. افتح **قاعدة المعرفة** من القائمة الجانبية.
2. اختر المجلد المناسب.
3. اضغط **New article** واكتب المحتوى.

- يصلح للشحن السريع
- لا يصلح للمنتجات المخصصة
```

## الروابط والصور

```markdown
اقرأ أيضاً [الحالات والنشر](https://example.com/path).

![وصف مختصر للصورة](https://example.com/image.png)
```

داخل حساب كرزون: اربط الصفحات ذات الصلة بروابط مساعدة حقيقية، وضع الصور من مرفقات المقالة أو مدير الملفات عندما يناسب سير عملك — الوصف البديل (`![...]`) يساعد الفهم إن لم تُحمَّل الصورة.

## الجداول

مناسبة لمقارنة حالات، خطط، أو «افعل / لا تفعل».

```markdown
| الحالة | يراها العميل؟ | يعتمد عليها المساعد؟ |
| --- | --- | --- |
| مسودة | لا | لا |
| منشور وعام | نعم | نعم |
| منشور وخاص | لا للجمهور العام | حسب إعدادك |
```

## الاقتباس وكتل التعليمات

~~~~markdown
> لا تعد بالتعويض قبل مراجعة السياسة المعتمدة.

تفاصيل تقنية أو نص يجب نسخه كما هو:

```
رقم الطلب: 12345
الحالة: قيد التوصيل
```
~~~~

استخدم الاقتباس لتحذير قصير؛ والكتلة ذات الخلفية لنصوص ثابتة (أكواد تتبع، صيغ رد) حتى لا تُفسَّر كفقرات عادية.

## مثال مقالة جاهزة للنسخ

انسخ الهيكل التالي إلى مقالة جديدة وعدّل النصوص لعملك:

```markdown
## متى ينطبق هذا؟

ينطبق على الطلبات المدفوعة خلال **١٤ يوماً** من الاستلام، إن كان المنتج بحالته الأصلية.

## الخطوات

1. راسل الدعم من نفس رقم الطلب.
2. أرفق صورة للمنتج إن وُجد عيب.
3. انتظر تأكيد الاسترجاع قبل إرسال الشحنة.

## لا ينطبق على

- المنتجات المخصصة بعد التصنيع
- بطاقات الهدايا المستخدمة جزئياً

## ماذا يقول الموظف؟

> تم استلام طلب الاسترجاع. سنؤكد خلال يوم عمل واحد.

## ذات صلة

- [سياسة الشحن](#)
- [تتبع الطلب](#)
```

## كتابة تساعد المساعد

المساعد يعتمد على المقالات **المنشورة**. Markdown الجيد يزيد وضوح الاسترجاع:

| افعل | لماذا |
| --- | --- |
| عنوان قسم = سؤال العميل | يطابق نية البحث |
| فقرة قصيرة تحت كل عنوان | إجابة واحدة واضحة |
| قائمة للشروط والاستثناءات | يقلّل خلط «نعم» و«لا» |
| جدول للمقارنة | أفضل من فقرة طويلة متشعّبة |
| تجنّب صفحة واحدة لكل شيء | مقالة واحدة لفكرة واحدة |

بحث شريط المستكشف يبحث العناوين والمجلدات فقط — جودة Markdown لا تغني عن [النشر](/ar/help-center/guides/knowledge-base/publish)، لكنها تجعل محتوى المعرفة أوضح حين يستدعيه المساعد.

## أخطاء شائعة

| الخطأ | النتيجة | التصحيح |
| --- | --- | --- |
| لصق من Word مع تنسيق خفي | معاينة غريبة أو رموز زائدة | نص نظيف + Markdown يدوي |
| عنوان بلا مسافة بعد `#` | لا يظهر كعنوان | `## عنوان` وليس `##عنوان` |
| قائمة بلا سطر فارغ قبلها | تلتصق بالفقرة السابقة | سطر فارغ ثم `-` أو `1.` |
| مقالة بلا عناوين فرعية | صعب على العميل والمساعد | قسّم بـ `##` |
| نشر مسودة ناقصة لأن «الشكل جاهز» | معرفة خاطئة للعميل | راجع ثم انشر |
