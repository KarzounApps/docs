## Introduction

The Technology Provider model is an innovative partnership framework that brings together platforms and Karzon to deliver a powerful solution for the WhatsApp Business platform. This model enables platforms to act as WhatsApp service providers, while **Karzon**, as an **Official WhatsApp Solution Partner**, manages all WhatsApp messaging services in the background, from the initial onboarding process through ongoing maintenance.

This document serves as a comprehensive guide, outlining the seamless integration process for technology providers looking to leverage WhatsApp Business platform solutions through Karzon’s expertise. The guide covers a range of essential aspects, including business considerations and technical details involved in the integration process.

---

## Key Steps

Welcome to the journey of joining the Technology Provider program! In the following sections, we will guide you through a three-phase process including **Setup**, **Integration**, and **Launch**. This guide will provide you with a clear handbook to successfully onboard with Meta and Karzon and maximize the capabilities of WhatsApp for your platform.

### Overview of Phases

**Phase 1: Setup**  
The setup phase involves business-level procedures. This includes creating the account and submitting basic information for account verification. Simultaneously, your Karzon account manager will assist you in configuring the necessary components on the Karzon platform in preparation for the integration phase.

**Phase 2: Integration**  
This phase covers the technical integration setup between your platform and Karzon, including embedding the WhatsApp Embedded Signup interface, applying for required permissions, and undergoing Meta’s app review.

**Phase 3: Launch**  
After completing all integration steps, you can plan for final testing and launch to your end customers.

### 2.3. Retrieving Account Data after Embedded Signup

After the client completes the Embedded Signup process, you need to obtain the necessary account data to integrate with Karzon. This section explains in detail how to get the **Access Token**, **WABA ID**, and **Phone Number ID**.

#### Phase 1: Receiving Data from JavaScript

When the client successfully completes Embedded Signup, data is returned via two channels:

**A. Message Event Listener** (contains account identifiers):

```javascript
window.addEventListener('message', (event) => {
if (!event.origin.endsWith('facebook.com')) return;
try {
const data = JSON.parse(event.data);
if (data.type === 'WA_EMBEDDED_SIGNUP' && data.event === 'FINISH') {
// Received data:
const wabaId = data.data.waba_id; // WhatsApp Business Account ID
const phoneNumberId = data.data.phone_number_id; // Phone Number ID
const businessId = data.data.business_id; // Business Manager ID

      // Send this data to your server
      fetch('/api/save-waba-info', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ wabaId, phoneNumberId, businessId })
      });
    }

} catch (error) {
console.error('Error:', error);
}
});

```

**B. Response Callback** (contains Authorization Code):

```javascript
const fbLoginCallback = (response) => {
  if (response.authResponse) {
    const code = response.authResponse.code;  // Authorization Code

    // This code is valid for only 30 seconds!
    // It must be sent immediately to your server
    fetch('/api/exchange-code', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ code })
    });
  }
};
```

#### Step 2: Exchange Authorization Code for Access Token

On your server, you need to exchange the Authorization Code to obtain an Access Token:

**API Endpoint:**

```
GET https://graph.facebook.com/v24.0/oauth/access_token
```

**Parameters:**

- `client_id`: Your App ID
- `client_secret`: Your App Secret
- `code`: Authorization Code received from JavaScript

**Example (Node.js):**

```javascript
async function exchangeCodeForToken(code) {
  const url =
    `https://graph.facebook.com/v24.0/oauth/access_token?` +
    `client_id=${process.env.APP_ID}&` +
    `client_secret=${process.env.APP_SECRET}&` +
    `code=${code}`;

  const response = await fetch(url);
  const data = await response.json();

  // data.access_token is the required Access Token
  return data.access_token;
}
```

**Example (cURL):**

```bash
curl -X GET "https://graph.facebook.com/v24.0/oauth/access_token?\
client_id=YOUR_APP_ID&\
client_secret=YOUR_APP_SECRET&\
code=AUTHORIZATION_CODE"
```

**Response:**

```json
{
  "access_token": "EAAxxxxxxxxxxxxx",
  "token_type": "bearer"
}
```

#### Step 3: Use Access Token to Retrieve Additional Details

After obtaining the Access Token, you can use it to get more information about the account:

**A. Get WABA Details:**

```bash
curl -X GET "https://graph.facebook.com/v24.0/{WABA_ID}?\
fields=id,name,currency,message_template_namespace,timezone_id&\
access_token=ACCESS_TOKEN"
```

**B. Get Phone Number Details:**

```bash
curl -X GET "https://graph.facebook.com/v24.0/{PHONE_NUMBER_ID}?\
fields=id,display_phone_number,verified_name,quality_rating&\
access_token=ACCESS_TOKEN"
```

**C. Get All Phone Numbers in WABA:**

```bash
curl -X GET "https://graph.facebook.com/v24.0/{WABA_ID}/phone_numbers?\
access_token=ACCESS_TOKEN"
```

#### Step 4: Register Phone Number (Required)

Before using the phone number to send messages, it must be registered:

```bash
curl -X POST "https://graph.facebook.com/v24.0/{PHONE_NUMBER_ID}/register?\
messaging_product=whatsapp&\
pin=YOUR_2FA_PIN&\
access_token=ACCESS_TOKEN"
```

> **Note:** If you do not have a 2FA PIN, you can omit this parameter initially, but it is strongly recommended to set it up later.

#### Step 5: Subscribe to Webhooks (Required)

To receive messages and updates, you must subscribe to Webhooks:

```bash
curl -X POST "https://graph.facebook.com/v24.0/{WABA_ID}/subscribed_apps?\
access_token=ACCESS_TOKEN"
```

## 3. Advanced Topics

### 3.1. Webhooks Setup

Webhooks are used to notify your platform of real-time events, such as receiving a new message from a client or an update on delivery status.

#### Webhook Settings

- **Webhook URL:** You must provide Karzoun with a URL (must be HTTPS) to receive events.
- **Verification:** Karzoun will send a `GET` request to the URL with `hub.mode`, `hub.challenge`, and `hub.verify_token`. Your server must respond with the `hub.challenge` to confirm the setup.

#### Supported Events

| Event               | Description                                                     |
| ------------------- | --------------------------------------------------------------- |
| `message.received`  | When a new message is received from a client                    |
| `message.delivered` | When a message is successfully delivered to the client’s device |
| `message.read`      | When the client reads the message                               |
| `account.updated`   | When account information is updated                             |

#### Example Payload for `message.received`

```json
{
  "event": "message.received",
  "timestamp": 1673683200,
  "waba_id": "123456789012345",
  "data": {
    "message_id": "wamid.xxx",
    "from": {
      "name": "John Doe",
      "phone_number": "+966501234567"
    },
    "message": {
      "type": "text",
      "body": "Hello, can I get some help?"
    }
  }
}
```

#### Webhook Security

To ensure that Webhooks originate from Karzoun, an `X-Karzoun-Signature` header is sent with each request. You must verify this signature using the HMAC-SHA256 algorithm and the Secret Key provided to you.

```javascript
// Example for verifying the signature (Node.js)
const crypto = require('crypto');

function verifyWebhookSignature(payload, signature, secret) {
const expectedSignature = 'sha256=' + crypto
.createHmac('sha256', secret)
.update(JSON.stringify(payload))
.digest('hex');
return crypto.timingSafeEqual(
Buffer.from(signature),
Buffer.from(expectedSignature)
);
}

```

End customers who are onboarded via embedded registration (configured for a partnership solution) subscribe to Karzoun's **Credit Line**. Karzoun is responsible for invoicing you for the solution based on the API usage by the end customer. You can charge your customers directly for the solution or service you provide.

**Billing Model:**
- Karzoun pays Meta directly
- Karzoun invoices the technology provider (you) monthly
- You invoice your end customers according to your business model

### 3.3. Revoking Permissions and Terminating Partnership

If you need to revoke access permissions or terminate the partnership with a specific customer:

1. Go to **Dashboard → WhatsApp → Partnership Solutions**
2. Select the solution to be disabled
3. Click **"Disable Solution"** or **"Remove Access"**
4. Confirm the action

**Note:** Revoking permissions does not delete the customer's WhatsApp account; it only removes the shared access permissions.
