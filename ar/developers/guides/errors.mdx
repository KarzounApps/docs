---
title: "الأخطاء"
description: "اقرأ رداً فاشلاً من GraphQL في كرزون وأصلحه."
---

الطلب الفاشل ما زال يعيد JSON. اقرأ `errors[0].message` أولاً. حالة HTTP تكون 200 لكثير من أخطاء GraphQL، و401 عندما تُرفض بيانات الاعتماد نفسها.

```json
{
  "errors": [
    {
      "message": "Login required",
      "path": ["tags"],
      "extensions": { "code": "INTERNAL_SERVER_ERROR" }
    }
  ],
  "data": { "tags": null }
}
```

قد تكون `data` مساوية لـ `null` للحقل الذي فشل وتبقى موجودة. لا تعامل جسماً فيه `errors` على أنه نجاح.

## ماذا تغيّر

| ما تراه | المعنى | ماذا تفعل |
| --- | --- | --- |
| HTTP 401، أو `Login required` | المفتاح أو رمز OAuth مفقود أو ملغى أو منتهٍ، أو أُرسل إلى الحساب الخطأ | أرسل `Authorization: Bearer kz_live_…` إلى `https://YOUR_SUBDOMAIN.api.karzoun.chat/graphql`. أنشئ مفتاحاً جديداً إن كان هذا ملغى. |
| `Permission denied`، أو حقل طلبته مرفوض | نطاقات المفتاح، أو صلاحياتك، لا تشمل تلك العملية | أضف النطاق من **المطوّر ← مفاتيح API**، أو اطلب من المالك. جرّب الاستعلام نفسه في [ساحة التجربة](https://karzoun.chat/developer/playground) وأنت مسجّل بمستخدم يستطيع تشغيله. |
| `GRAPHQL_VALIDATION_FAILED` | حقل أو وسيط غير موجود في المخطط | قارن الاستعلام مع [مرجع الواجهة](/api-reference). الأسماء حساسة لحالة الأحرف. |
| الأداة أو الطلب يقول إن الرد أكبر من اللازم | القائمة تجاوزت ما يقبله العميل | خفّض `perPage` أو أضف مرشحاً. انظر [ترقيم الصفحات](/ar/developers/guides/pagination). |

قد يعيد الاستعلام `data` و`errors` معاً عندما يفشل حقل وينجح آخر. افحص `errors` حتى عندما تكون `data` موجودة.
