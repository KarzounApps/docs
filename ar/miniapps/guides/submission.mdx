ميني أب **ليست ذاتية النشر**. تبني تعريف JSON محلياً، وتختبره على واجهة مزوّدك، ثم تقدّمه إلى كرزون للمراجعة. بعد الموافقة، تسجّل كرزون ميني أب وتدرجه في السوق (أو تفعّله لبرنامج شركائك).

<Info>
  **لمن هذا** — المدمجون المستقلون و[الشركاء](/ar/partners) الذين يبنون موصلات لخدمات خارجية. تشغّل كرزون طبقة الاستضافة — وأنت تقدّم التعريف والأصول الداعمة.
</Info>

## قبل التقديم

1. **مستند مكتمل** — الهوية و`auth` و`actions` و(إن وُجدت) كتل `triggers` و`webhook` و`sync` و`source` وفق [مخطط المستند](/ar/miniapps/reference/document-schema).
2. **`ns` فريد** — مساحة أسماء بحروف صغيرة بصيغة kebab-case (مثل `my-service`). لا يمكن تغييره بعد الموافقة بدون تقديم جديد.
3. **بيانات السوق الوصفية** — `title` والأوصاف و`icon` و`logo` و`category` و`docsUrl`. انظر [قائمة السوق](/ar/miniapps/guides/marketplace).
4. **أصول المزوّد** — استضف `icon` و`logo` على روابط HTTPS تتحكم بها (SVG أو PNG). لا تستضيف كرزون أصول علامة الشركاء أثناء المراجعة.
5. **بيانات اعتماد الاختبار** — مفاتيح API لبيئة الاختبار أو تطبيق OAuth للمراجعين (انظر القائمة أدناه).
6. **رابط الويب هوك** — وثّق نمط نقطة نهاية كرزون: `https://{tenant-api}/miniapps/{ns}/webhooks` (يُوفَّر المضيف الدقيق أثناء التأهيل).

## حزمة التقديم

أرسل إلى جهة اتصال شريك كرزون أو `developers@karzoun.chat`:

| العنصر               | الصيغة                                                       |
| ------------------ | ------------------------------------------------------------- |
| تعريف ميني أب | ملف `.json` (مُنسَّق) أو رابط إلى مستودع خاص        |
| سجل التغييرات          | ما تغيّر إذا كان هذا تحديثاً                              |
| حساب اختبار       | متجر / حساب اختبار + بيانات اعتماد للمراجعين          |
| دليل الإعداد        | 3–5 خطوات للمستخدمين النهائيين (يمكن أن تطابق markdown في `description`)   |
| أحداث الويب هوك     | قائمة الأحداث المشتركة وحمولات عيّنة                  |

<Warning>
  **الأسرار في التقديمات** — لا تضمّن أسرار الإنتاج في JSON الذي تقدّمه. استخدم سلاسل فارغة في `auth.config` للقيم التي يوفّرها المستخدم. `client_id` / `client_secret` لتطبيقات OAuth **العامة** مقبولة عندما يتطلبها التدفق.
</Warning>

## عملية المراجعة

| المرحلة        | ما يحدث                                                                             |
| ------------ | ------------------------------------------------------------------------------------------ |
| **الاستلام**   | تتحقّق كرزون من المخطط والتسمية والأمان (`sensitiveKeys` والتحقق من الويب هوك)   |
| **ضمان الجودة**       | يثبّت المراجعون في مستأجر اختبار، ويربطون المصادقة، ويشغّلون الإجراءات، ويطلقون ويب هوك اختبارية      |
| **الموافقة** | يُسجَّل التعريف؛ وتعيّن كرزون `status: 'public'` (أو للشركاء فقط)         |
| **التحديثات**  | قدّم إصداراً جديداً مع زيادة `version`؛ تنشر كرزون بعد المراجعة           |

المدة المعتادة **5–10 أيام عمل** حسب التعقيد (OAuth + ويب هوك + مزامنة تستغرق أطول من bearer-token + إجراءات).

## بعد الموافقة

- يظهر ميني أبك في **السوق** ليثبّته المستأجرون.
- Redirect URI لـ OAuth لتسجيله لدى مزوّدك: `{SAAS_API_URL}/miniapps/{ns}/oauth2`
- رابط الويب هوك الذي يسجّله المستأجرون: `{SAAS_API_URL}/miniapps/{ns}/webhooks`
- للتغييرات الكاسرة، زد `version` وقدّم مجدداً — لا تغيّر `ns`.

## تحديث ميني أب معتمد

1. عدّل تعريف JSON محلياً.
2. زد `version` (semver).
3. قدّم الحزمة مجدداً مع سجل تغييرات قصير.
4. تطرح كرزون بعد ضمان الجودة — تبقى التثبيتات الحالية تعمل ما لم توثّق خطوات الترحيل.
