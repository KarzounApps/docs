---
title: "Quickstart"
description: "Make your first Karzoun GraphQL API call."
---

You will create a key, call your workspace, and read a list of tags.

<Steps>
  <Step title="Create an API key">
    Open **Developer → API keys** (`/developer/api-keys`). Create a **personal** key, leave the scopes your account is allowed to use, and copy the secret. It starts with `kz_live_` and is shown once.

    <Warning>
      Do not commit the key or paste it into frontend code.
    </Warning>
  </Step>
  <Step title="Copy your API URL">
    Replace `YOUR_SUBDOMAIN` with the subdomain of your workspace. If you sign in at `acme.karzoun.chat`, the API is:

    ```
    https://acme.api.karzoun.chat/graphql
    ```
  </Step>
  <Step title="Run this query">
    The query and the curl below are the same request.

    <CodeGroup>
    ```graphql
    query {
      tags(page: 1, perPage: 5) {
        data {
          _id
          name
        }
        pagination {
          totalCount
        }
      }
    }
    ```

    ```bash
    curl -X POST 'https://YOUR_SUBDOMAIN.api.karzoun.chat/graphql' \
      -H 'Content-Type: application/json' \
      -H 'Authorization: Bearer kz_live_YOUR_API_KEY' \
      -d '{"query":"query { tags(page: 1, perPage: 5) { data { _id name } pagination { totalCount } } }"}'
    ```
    </CodeGroup>

    A working key returns JSON like this:

    ```json
    {
      "data": {
        "tags": {
          "data": [{ "_id": "…", "name": "VIP" }],
          "pagination": { "totalCount": 12 }
        }
      }
    }
    ```

    `data` may be an empty list. That still means the call worked. If you get `errors` instead, the key was missing, revoked, or the query does not match the schema. See [Errors](/developers/guides/errors).
  </Step>
</Steps>

The same call works in the [Playground](https://karzoun.chat/developer/playground) while you are signed in. Add the `Authorization` header there only when you want to test the key rather than your own login.
